The 64 Bit version of Blassic

Blassic was originally coded for 32-bit processors. This made the commands PEEK and POKE fail on 64-bit machines. This caused some issues since modifying addresses after SYSVARPTR caused segmentation faults. In particular, changing the behavior of the LOCATE commands so that abcissa comes first (as on the Amstrad CPC) is only possible using a POKE SYSVARPTR+30,... command.

To restore a correct behavior of the PEEK/POKE command, I have changed BlInteger from 32bit to 64bit.

So far, the following issues have been encountered

  1. Programs that don't properly terminate with END will cause a Segmentation fault with si_addr 0xnnnn si_ptr (nil) and si_code 1
  2. LABEL nnn and GOTO LABEL nnn also cause a segfault.

The other commands operate normally.
